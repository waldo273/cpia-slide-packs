Topic F0 · Goals

Goals of malware analysis

  • Determine if a file is malicious the first and most important judgement
  • Extract indicators of compromise the artefacts that allow detection elsewhere
  • Create host-based signatures for AV and host intrusion detection
  • Create network signatures to spot C2 and exfiltration traffic
  • Determine the capabilities what the malicious code can actually do
  • Update existing signatures when a sample exposes new behaviour
Topic F0 · Indicators of compromise

What counts as an IOC?

  • File hashes cryptographic digests such as MD5, and fuzzy hashes such as SSDeep
  • Filenames and folder locations the paths the malware creates or persists in
  • Registry keys persistence and configuration locations
  • Strings URLs, domains, IP addresses, commands
  • Network traffic patterns the shape of C2 communication
  • Binary functions and encryption and developer toolmarks

Topic F0 · OPSEC

Operations security — the don'ts

  • Do not allow malware to connect back to the attacker from your lab
  • Do not manually connect to attacker infrastructure
  • Do not scan attacker infrastructure no port or vulnerability scans
  • Do not use discovered credentials such as FTP usernames or passwords
Topic F0 · OPSEC

Operations security — the do's

  • Neuter extensions rename bad.exe to bad.exe_ so it cannot be run accidentally
  • Password-protect archives zip samples with the password 'infected'
  • Clearly label media any portable media containing malicious code
  • Use a throwaway VM never your corporate gold build image
  • Disable USB autorun and beware browsers preloading links you search
Topic F0 · OPSEC

OPSEC: staying anonymous

  • Sometimes you must reach attacker infrastructure for example to download exploit-kit payloads
  • The Onion Router (TOR) routes traffic through an anonymous overlay network
  • VPN services mask your true source address
  • Cloud upload risk files sent to VirusTotal are shared with subscribers and AV vendors
Topic F2 · Functionality identification

Identifying what a sample does — statically

  • Static analysis examining code, binaries and headers without executing — safe and efficient
  • Information extraction embedded strings, imports, exports, file headers
  • Strings utility extracts printable ASCII and Unicode sequences — URLs, paths, commands
  • Import hashing (imphash) a Mandiant technique hashing libraries, API names and their order
  • NSRL National Software Reference Library — known-good hash sets to filter out
  • PEiD detects common packers, cryptors and compilers

Topic F1 · Anti-reverse engineering

The aim: conceal, but stay recoverable

  • Concealment goals most packers try to conceal information — intellectual property or malware
  • Recovery requirement the information must be recoverable at run time
  • The unpacking code does the work the packer ships a stub that restores the original code
  • Anti-RE categories anti-disassembly, anti-debugging, anti-virtualisation, anti-sandboxing
Topic F1 · Anti-disassembly

Anti-disassembly methods

  • Overlapping instructions jumping into the middle of another instruction
  • Linear disassembly abuse garbage following a call, jump or conditional jump
  • Stack abuse modifying return addresses, e.g. call $+5; add [esp],5; retn
  • Purpose inhibits static analysis — disassembly and decompilation
Topic F1 · Anti-debugging

Anti-debugging and anti-virtualisation

  • Anti-debugging inhibits dynamic analysis — debugging and tracing
  • Anti-virtualisation detects the VM and changes behaviour or refuses to run
  • Anti-sandboxing detects the analysis environment and evades it
  • High-profile bugs known flaws in common debuggers and disassemblers are weaponised
  • Defeat identify and neutralise the checks, then unpack and analyse
Topic F1 · Unpacking

Unpacking the binary

  1. Load the packed binary in a debugger
    start execution in a controlled way
  2. Identify the unpacking code
    and any anti-debugging code
  3. Identify the original entry point (OEP)
    the start of the real program
  4. Run to the OEP
    let the unpacking stub do its work
  5. Dump the process
    capture the unpacked image from memory
  6. Reconstruct the import table
    restore the functions called from other libraries

Topic F3 · Windows NT architecture

Kernel mode and user mode

  • Two privilege levels the processor enforces rings that control access to resources
  • Kernel mode (Ring 0) highest privilege — drivers, the core of the OS, direct hardware access
  • User mode (Ring 3) applications run here with restricted access to hardware
  • Context switching transitions between modes are mediated by the OS
  • Malware targeting kernel-mode rootkits are far harder to detect than user-mode code
Topic F3 · Windows NT architecture

Processes, threads and the executive

Component Role
ProcessAn isolated address space; each process gets its own memory segment
ThreadThe unit of execution within a process
ExecutiveThe kernel-mode services — memory, I/O, process and object management
SubsystemsEnvironment subsystems present the Win32 API to applications
RegistryConfiguration store malware abuses for persistence
Topic F4 · Windows API development

How code calls the operating system

  • The Win32 API the set of functions applications call to use Windows services
  • Imports at load time functions resolved via the import table in the PE
  • Imports at run time LoadLibrary / GetModuleHandle plus GetProcAddress
  • Malware preference run-time resolution avoids obvious import strings
  • API hashing malware stores a hash of the function name and resolves it dynamically
Topic F4 · Windows API development

API hashing in practice

  • Avoids readable strings no plain-text API names for an analyst to spot
  • Less data to store a single 32-bit hash replaces a long name
  • Bespoke resolvers custom GetModuleHandle and GetProcAddress replacements
  • Typical hash ROL(hash, 5) XOR each byte of the name

Calling conventions

Convention Argument passing Stack cleanup

stdcallArguments pushed on the stack, right to leftCallee cleans up
fastcallFirst arguments passed in registers (ECX, EDX)Callee cleans up
Topic F5 · Binary code structure

Compiler-generated constructs

  • Function prologue and epilogue setup and teardown of the stack frame
  • Stack frames local variables, saved registers and return addresses live here
  • C++ objects methods compiled as functions; objects carry a pointer to their data
  • Virtual function table (vtable) a table of pointers to the object's virtual methods
  • Recognising these lets you reconstruct high-level intent from raw assembly
Topic F6 · Cryptographic techniques

Crypto in malware

  • Hashing fingerprinting, integrity checks, API and string obfuscation
  • Symmetric encryption stream and block ciphers to hide payloads and C2 traffic
  • Asymmetric encryption public-key crypto for key exchange and secure C2
  • Encoding vs encryption Base64 is encoding, not encryption — it offers no real secrecy
  • Custom algorithms malware authors often invent bespoke ciphers to defeat signatures
Topic F7 · Processor architectures

The x86 instruction set and registers

  • Instruction set the interface between CPU hardware and the software running on it
  • An instruction a binary message to the CPU to perform an action next cycle
  • OpCode and operands an operation code plus addresses, representable by mnemonics
  • RAX 64-bit general register; splits into EAX (32), AX (16), AH and AL (8-bit halves)
  • RBX / RCX / RDX RCX is the loop counter; RDX is the overflow for multiply and divide
Topic F7 · Processor architectures

Stack and string registers

Register Purpose
RBPBase pointer — stack operations and location counters
RSPStack pointer — top of the stack
RSISource index — source for string commands, increments when used
RDIDestination index — destination for string commands, increments when used
Topic F7 · Processor architectures

x64 and virtual memory

  • x64 registers identical to x86 plus R8 to R15 — 16 general-purpose registers total
  • Physical memory any storage device — cache, RAM, disk, SSD — each with a physical address
  • Virtual memory each process gets its own segment, possibly on different physical modules, appearing continuous
  • The MMU Memory Management Unit translates virtual addresses into physical ones
Topic F7 · Processor architectures

Virtualisation and its flaws

  • Virtualisation hardware virtualisation of whole machines (VMs)
  • Containerisation operating-system-level virtualisation
  • Privilege rings the host OS lives at ring 0; the guest runs at a higher ring
  • Meltdown a flaw letting a malicious process access all of RAM
  • Spectre a flaw allowing access to protected data by observing processor actions
Topic F8 · Windows executable formats

The Portable Executable (PE) format

  • Common PE types EXE, SCR, DLL, CPL, OCX, SYS
  • Three data parts a single header, multiple sections, and multiple data directories
  • Data directories may be stored within or after the sections
  • PE types EXE is an executable program; DLL is a dynamically-linkable library
  • Reading a PE is the first step in identifying malicious structure
Topic F8 · Headers

DOS, NT, file and optional headers

Header Key contents
IMAGE_DOS_HEADERStarts with 'MZ'; 16-bit DOS stub; pointer to the NT headers
IMAGE_NT_HEADERSStarts with 'PE' plus two nulls; contains the file and optional headers
IMAGE_FILE_HEADERCPU required, number of sections, timestamp, symbol table, EXE/DLL flag
IMAGE_OPTIONAL_HEADERVersions, base addresses, size of image, entry point, data directories
Topic F8 · Sections

PE sections

  • Code executable content; every EXE has at least one code section
  • Data information used by the code — read-only, read-write initialised or uninitialised
  • Imports functions resolved from other libraries at load or run time
  • Exports functions callable by other executables — mostly in DLLs
  • Resources dialog boxes, icons, images, strings, manifests
  • Relocations the changes needed when a file loads away from its preferred base
Topic F8 · Imports and relocations

Imports by hash and ASLR

  • Imports by hash malware hashes API names to avoid readable strings
  • Run-time resolving missing imports indicate LoadLibrary / GetProcAddress
  • Relocations most PEs must be relocatable
  • ASLR address space layout randomisation loads at a random base, triggering relocations
Topic F8 · The PE loader and tools

How a PE loads, and spotting bad ones

  • The PE loader parse headers, parse section table, map sections, resolve imports, call entry point
  • Tools DumpBin (command line), PE viewer GUI, hex editor
  • Indicators of a bad PE multiple or bogus headers, missing or extra sections, bogus section data
  • Inspection check timestamps, versions, data-directory sizes, section names and permissions

Topic F9 · Hiding techniques

What is a rootkit?

  • Administrative privilege rootkits obtain administrative privileges on the system
  • Origins originally used by network and system administrators
  • Now stealth malware widely referred to as stealth-type malware
  • Capabilities maintain presence, execute remote commands, disable security software, alter files, install more malware
Topic F9 · Hiding techniques

How rootkits remain hidden

  • Clear security logs erase user audit logs to hide activity
  • Delete generated evidence and hide files and directories
  • Timing attacks sleep to avoid automated malware analysis
  • Process injection such as DLL injection into svchost.exe or explorer.exe
  • SSDT patching redirect kernel-mode function pointers
  • Filter drivers and process list manipulation to hide their own presence
Topic F9 · Process injection

Process injection techniques

Technique Approach
Classic DLL injectionFind target, allocate space, load code into the target, execute it remotely
PE injectionFind target, allocate space, copy the malicious code in, execute it remotely
Process hollowingFind target, unmap its legitimate code, overwrite with malicious code, execute it remotely
Topic F9 · SSDT and filter drivers

Kernel hiding mechanisms

  • SSDT the System Service Descriptor Table holds pointers to kernel-mode functions
  • SSDT fields ServiceTable, CounterTable, ServiceLimit, ArgumentTable
  • SSDT patching redirecting those pointers so the system lies about what exists
  • Filter drivers sit in the driver stack and filter requests, hiding files or resources
  • Process list manipulation image-name and parent-process exploitation, and process hollowing
Topic F10 · Malware reporting

Signatures and fuzzy hashing

  • SSDeep fuzzy hashing that produces comparable hashes for similar files
  • Signature identification identifying a sample so it can be reported and detected
  • YARA open-source, multi-platform pattern, string and signature matching
  • YARA rules logical rules using Perl-based regular expressions
  • Footprint and cleanup recording the sample's footprint to support removal
Topic F10 · YARA in practice

Writing effective YARA rules

  1. Identify the target
    select the executable to analyse
  2. Extract packed strings
    run string extraction in ASCII and Unicode modes
  3. Extract unpacked strings
    execute the malware and gather more strings with Process Explorer
  4. Develop rules
    create separate rules for the packed and unpacked states
  5. Match on unique strings
    malware-specific and incident-specific indicators
Topic F10 · Infection vectors

How malware gets in

  • Infected executables and documents malware in EXEs, DLLs, Office macros and JavaScript
  • Drive-by downloads unintentional downloads from compromised websites
  • USB and shared drives infected files copied or auto-executed from removable media
  • Passive exploitation unpatched services exploited without user interaction
  • Email-based attacks phishing with malicious attachments or links
Topic F10 · Static analysis & imphash

Reporting supports detection

  • Static analysis examining a file without executing it — safe and efficient
  • Import hashing (imphash) hashes libraries, API names and their order to group related samples
  • NSRL the National Software Reference Library filters out known-good files
  • PEiD detects packers, cryptors and compilers
  • Strings utility extracts printable ASCII and Unicode sequences for clues
Topic F11 · Binary obfuscation

Obfuscating the binary

  • Packing and compression the original code is hidden until run time
  • Encryption payload and strings encrypted so static analysis reveals little
  • String obfuscation encoding strings to defeat signature and strings-utility detection
  • Anti-RE integration obfuscation combined with anti-disassembly and anti-debugging
  • The goal raise the cost of analysis and delay detection
Topic F12 · Behavioural analysis

Watching the malware run

  • Dynamic analysis run the sample in a controlled environment and observe
  • Sandbox or VM isolate the sample so it cannot harm the host
  • Observe behaviour files created, registry keys written, processes spawned, network traffic
  • Timing awareness some malware sleeps or detects the sandbox to avoid revealing behaviour
  • Combine with static behavioural findings complement static analysis of the binary
