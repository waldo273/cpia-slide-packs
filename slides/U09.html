unit objectives

By the end of this unit you will be able to

  • Apply the ACPO principles to seizure, preservation and examination of evidence
  • Perform host-based acquisition with write blockers and forensic imaging tools
  • Verify image integrity using MD5 and SHA1 computed hashes
  • Stand up a live analysis lab with a grab pack and hardened sandboxes
  • Explain disk partitioning and file systems FAT and NTFS, and their core structures
  • Describe ACLs, SIDs, unallocated space and EFS and BitLocker encryption
Topic E1 · Acquisition

Host-based data acquisition — the fundamentals

  • Static and dynamic gathering dead-box imaging versus live evidence capture
  • Image formats raw (dd), E01/EWF and others used by forensic tools
  • Local acquisition a write-blocked drive imaged on the bench
  • Remote acquisition imaging a live host across the network
  • Core objective a bit-for-bit copy whose integrity can be proven
Topic E1 · ACPO

ACPO Principle 1

  • Principle 1 no action taken by Police or their agents should change data held on a computer or other storage media which may subsequently be relied upon in Court
  • Isolate the device remove it from the network at seizure
  • Turn the device off at the point of seizure where appropriate
  • Consider local policies before powering down
  • Mobiles and tablets place in a shielded Faraday container
  • Use forensic software and plan the examination to avoid data loss
Topic E1 · ACPO

The Faraday bag

  • Purpose prevents a handset communicating with a mobile phone network
  • Battery drain a handset inside a Faraday bag depletes rapidly
  • Correct sealing fold the top of the bag over, otherwise the signal may not be blocked
  • Wipe mode risk remote-wipe commands cannot reach a shielded device
Topic E1 · ACPO

ACPO Principles 2, 3 and 4

  1. Principle 2
    in exceptional circumstances a competent person may access original data, and must be able to explain their actions
  2. Principle 3
    an audit trail or record of all processes applied to the evidence must be created and preserved
  3. Principle 4
    the case officer (OIC) is responsible for ensuring the law and these principles are adhered to
Topic E1 · Acquisition

Seizure and the audit trail

  • Photograph the scene record the status of the exhibit at the point of seizure
  • Record on / off state and the condition of the exhibit
  • Maintain a log of every action taken with the exhibit
  • Record changes of data e.g. accidental changes during acquisition
  • Note tools and versions including product names and version numbers
  • Exhibit continuity seizing personnel trained and equipped for the task
Topic E1 · Imaging

Imaging prerequisites — the jump kit

  • Write blocking device a hardware write blocker stops writes to the source
  • Data and power cables adaptors for the range of target drives
  • Forensic imaging software FTK Imager, dd, ddrescue, DEFT
  • Verification hashes MD5 and SHA1 computed and compared
  • Clean media target drives ready for the image
Topic E1 · Imaging

Imaging with FTK Imager and ddrescue

  • FTK Imager GUI-based imaging with computed MD5 and SHA1 checksums
  • Image verification checksums recomputed and compared after acquisition
  • Hash mismatch a mismatch invalidates the image and requires re-acquisition
  • DEFT a Linux live forensic distribution used at the bench
  • ddrescue recovers data from failing media; -n writes only good sectors, -d uses direct disk access on error areas

Topic E2 · Laboratory

Standing up a live analysis laboratory

  • The grab pack hardware, software, cabling and incident checklists
  • Hardware write blockers, SATA/PATA/IDE/SCSI adaptors, imaging laptop, storage drives
  • Network infrastructure an isolated or controlled lab network
  • Documentation incident checklist, call lists, communication plan
  • Best practice virtualise — fewer machines, snapshots, easy to clean
Topic E2 · Laboratory

Virtualisation versus standalone machines

Approach Advantages Disadvantages
VMware server (free)Less dedicated machines; snapshots; host-only networking; easy to cleanComplicated to configure; needs lots of RAM; detectable by malware
Multiple standalone machinesFast to set up; accurately reflects the original; hard to mis-set-upExpensive; requires dedicated network infrastructure
Topic E2 · Laboratory

Host hardening and the sandbox

  • What hardening is increasing defences, decreasing ease of infiltration, limiting malware spread
  • Why harden prevent further infections and protect the analysis lab
  • Methods passwords and firewalls; low privileges, elevating as needed
  • Air-gapped network physically isolated from the corporate estate
  • Sandbox environments a complex network of replicable machines, normally VMs
  • Disposable and realistic easily re-set or rolled back, difficult to break out of
Topic E2 · Laboratory

Lab setup process and tooling

  1. Build the VMs
    install multiple VMs to simulate the infected network; install OSs and applications
  2. Simulate the environment
    web host, DNS, FTP and file servers as needed
  3. Snapshot
    take a clean snapshot before installing service packs and patches
  4. Install analysis tools
    hash tools, rootkit identifiers; verify tool integrity
  5. Snapshot again
    then begin behaviour and code analysis
  6. Re-hash and compare
    verify tools have not been altered during the analysis
Topic E2 · Laboratory

Booting to an image

  • Pros realistic and fast — boots the acquired image directly
  • Cons licensing issues and cost; the image must be capable of booting
  • Behaviour analysis tools system information, process monitoring, file monitors, registry monitors
  • More robust than Task Manager specialist process-monitoring tools give deeper visibility
  • Do not remove malware yet virus and rootkit scanners identify but do not clean at this stage
  • Use multiple tools cross-check with ADS viewers, port scanners, hex editors
Topic E3 · File systems

Disk partitioning and file systems

  • Partitioning tasks to create, resize and delete partitions; logical segments of a physical device
  • MBR limit only room for four partition entries in the master boot record
  • Partition types primary, extended and logical partitions overcome the limit
  • File systems organise files on hard discs, USB drives and tapes
  • FAT and NTFS FAT12/16/32 for older and removable media; NTFS is the modern Windows default
Topic E3 · FAT

FAT and the directory entry

Variant FAT entry Max clusters Max volume
FAT1212 bits~4,09616 MB
FAT1616 bits~65,5362 GB
FAT3228 bits~268,435,4562 TB
  • Directory entries tell where the first cluster of a file is located
  • Entry metadata name, file size, extension, attributes, date and time
  • Two FAT copies FAT1 and FAT2 protect against table corruption
Topic E3 · NTFS

NTFS, the MFT and attributes

  • NTFS Microsoft's high-performance, reliable and secure file system
  • Features access control lists and the encrypted file system
  • Master File Table ($MFT) stores file metadata as attributes
  • Resident attributes $STANDARD_INFORMATION, $FILE_NAME, $DATA
  • Non-resident attributes $BITMAP and others held outside the MFT record
  • $MFT and $Bitmap the metadata and allocation tables of the volume
Topic E3 · NTFS

ACLs, SIDs, unallocated space and encryption

  • Access Control Lists a list of permissions attached to an object — file and share permissions
  • Grants access to users and system processes
  • Security Identifiers (SIDs) uniquely identify users and groups; listed via the registry ProfileList or WMIC
  • Unallocated space deleted files can be recovered here by carving
  • EFS encrypts files on NTFS using the username and password plus DES or AES
  • BitLocker AES 128/256-bit volume encryption; manage-bde -status reveals volumes
