unit objectives

By the end of this unit you will be able to

  • Collect network traffic with packet analysers, sniffing tools and switches or routers
  • Design a collection system so enough data is captured without overwhelming devices
  • Explain SPAN ports and TAPs including aggregating TAPs and fibre access

Topic D1 · Traffic capture

Methods of data collection

  • What we collect packets of data on the network, carrying source and destination information
  • Tools packet analysers, sniffing tools, switches and routers
  • Why we collect intrusions, performance, quality of service (QoS)
  • The goal enough data to reconstruct the incident without overwhelming the capture device

Topic D1 · Traffic capture

Filtering captured traffic

  • Reduce network impact filtering lowers the load on the network
  • Reduce the data to analyse only the relevant traffic is kept
  • Work within storage limits the capture device's storage is finite
  • Typically at analysis stage filtering is usually performed when analysing
  • Filter by protocol, source and destination
Topic D1 · Traffic capture

Impact of traffic capture

  • Bridge capture? is it necessary to place a device between the target and the network?
  • Transparency can the capture device be made transparent to the traffic?
  • Attacker awareness will the attacker be alerted to the sniffing?
  • Design the system so that capture does not alter the very behaviour we are observing

Topic D1 · Traffic capture

Scope of the analysis

  • Focus on data required and on the suspect machines
  • Only capture what is needed avoid drowning the analysis in noise
  • Identify ports in use, network topology, security devices
  • Find available logs that can assist the investigation
  • Deployment location use network diagrams and the scope to focus the capture
Topic D1 · Traffic capture

Topic D1 · Traffic capture

Preserving network security and integrity

  • Encrypt captured files protect the data at rest
  • Secure the capture device physical and logical protection
  • Limit access to TAPs only authorised personnel
  • Remove SPAN ports after use leave the network as it was found
  • Assure integrity arguments and evidence that the captured data is sound
Topic D2 · Log sources

Data sources and network log sources

  • Identification is challenging every network differs from another
  • Intruders leave a trace the logs capture it if they are present and retained
  • Types of data source routers, switches, servers, computers, IDS, databases
  • Use the data to reconstruct the incident timeline
Topic D2 · Log sources

Topic D2 · Log sources

Syslog and Windows event logs

  • Syslog a method of logging messages about a system; records timestamps, IPs, severity and descriptive messages
  • Syslog server receives syslogs from network devices, listens and collects — assists the investigator
  • Windows event logs locally stored logs on each host
  • Three well-known logs Application, System and Security
  • Domain logs record user logins, machines, units, password changes and accessed resources
Topic D2 · Log sources

Questions to ask of any data source

  • How long is the data stored? retention windows vary by source
  • Is it overwritten after a period? older data may be gone
  • Is it stored securely? could it have been tampered with?
  • How will we handle volume? excessive data needs a plan
  • Correlate across sources the complete picture comes from joining many logs
Topic D3 · Config issues

Issue Examples

Topic D3 · Config issues

Detecting man-in-the-middle

  • ARP poisoning an attacker's MAC replaces the gateway's in the ARP table
  • Test with arp -a compare the gateway MAC against the known-good value
  • DNS spoofing a poisoned DNS response sends traffic to the attacker
  • Test with DNS lookups verify the resolved address matches the legitimate one
  • Compare before and after a changed gateway MAC is a red flag
Topic D3 · Config issues

Detecting firewall and proxy evasion

  • IP address spoofing forging the source address to bypass filters
  • Source routing forcing traffic along an unexpected path
  • Fragmentation splitting packets so rules miss the payload
  • IP addresses to access websites bypassing name-based proxy controls
  • Tunnelling ICMP tunnelling, ACK tunnelling, HTTP tunnelling

Topic D6 · Encryption

Analysis of traffic flows

  • Flows sequences of related packets examined for patterns
  • Flow analysis identify traffic patterns, isolate suspicious activity, analyse higher-layer protocols, extract data
  • Flow definitions quality of service (QoS), volume, directionality
  • Follow TCP stream reassemble a conversation in Wireshark
  • Flow tools tcpflow, pcapcat, tcpxtract for reconstruction and carving
Topic D6 · Encryption

Flow analysis techniques

  1. List conversations and flows
    get an overview of who talked to whom
  2. Export a flow
    extract the conversation of interest
  3. File and data carving
    recover files and data from the stream
  4. Active pattern matching
    IPs, ports, protocols and flags, directionality, volume
Topic D6 · Encryption

Fingerprinting

  • Channel fingerprinting a pattern that identifies a remote channel or tool
  • One source IP address a single host beaconing out
  • One or more destination IPs many targets from one source
  • Increasing destination ports ports climbing incrementally
  • Volume of packets unusual packet counts
  • SYN flags outbound a TCP protocol signature of scanning or probing
Topic D6 · Encryption

Weak obfuscation and deobfuscation

Scheme Description
XORByte-wise exclusive-or with a key; reversible with the same key
ADD / SUBArithmetic on bytes; used in tandem since they are not reversible alone
ROL / RORCircular bit rotations; used together as they are not reversible
ROTCaesar cipher over A–Z or the 94 printable ASCII characters
MultibyteLonger keys, often 4 or 8 bytes, typically XOR per block
Chained / loopbackEncoded output becomes the key for the next character
Topic D6 · Encryption

Deobfuscation

  • Deobfuscation making sense of something that has been encoded
  • XOR apply the same key again to recover the plaintext
  • BASE64 a common encoding layer to strip before analysis
  • Codebooks lookup tables replacing data with codes
  • The goal reduce weak obfuscation to readable content for the investigation
Topic D7 · C2

Botnets and command-and-control

  • Botnet a large network of compromised computers, infected with malicious code and remotely controlled by one or more cybercriminals
  • C&C servers the command-and-control infrastructure
  • Types centralised, distributed, and hybrid C&C
  • Uses spam distribution, DDoS, identity theft, online advertising fraud
Topic D7 · C2

C2 architectures compared

Type Advantages Weakness
CentralisedLow reaction time, good coordination power, easy monitoringSingle point of failure
DistributedHigh anonymity for botmasters, difficult to disarticulate, more robustMore complex to manage
HybridCombines centralised control with distributed bot groupsServant bots and client bots add complexity
Topic D7 · C2

Botnet lifecycle and detection

  • Lifecycle conception, recruitment, connection, marketing, execution, maintenance
  • Signature-based detection IDS/IPS detection of known botnets
  • Anomaly-based detection high latency, unusual ports, unusual system behaviour
  • DNS-based detection analysis of DNS traffic for bot-related names
  • Review traffic and logs IDS, IPS, web server access.log and error.log
Topic D8 · Exfiltration

Data exfiltration

  • Manual by an individual with physical access to a computer
  • Automated through malicious programming over a network
  • Access points the many ways data leaves the network
  • Attack paths obtained passwords, remote access, APTs — advanced persistent threats
  • FTP misconfiguration misconfigured servers, default passwords, plaintext credentials
Topic D8 · Exfiltration

Exfiltration vectors

  • Web applications an attacker uses their own browser to access data directly — ordinary, hard to suspect
  • WMI Windows Management Instrumentation used to move data
  • Covert channels VOIP tunnels, ICMP tunnels, DNS tunnels, HTTP tunnels
  • Encrypted transport all of these protocols can carry encrypted data out of the network
Topic D8 · Exfiltration

Behavioural analysis and prevention

  • Behavioural analysis automatically detect destinations that receive far more uploaded data than typical
  • Relevant fields bytes sent, client host/IP, destination host/IP (e.g. in proxy logs)
  • Watermarking an overt detection technique — track files and monitor what happens to them
  • Prevention secure endpoints, stronger IT controls, physical and logical security, DLP, inspection of traffic
Topic D9 · Incoming attacks

Public-facing services under attack

  • Public-facing services web servers, FTP servers, mail servers — accessible via the internet
  • Constant threat a steady stream of approaches against these services
  • Impact interruption and destruction
  • Detect via manual review of traffic, system performance, firewall and web server logs
Topic D9 · Incoming attacks

Detecting denial of service

  • High volume of incoming traffic a classic DoS signature
  • Single or multiple source IPs attackers may come from one or many addresses
  • Protocol abuse malformed handshakes, large ping packets
  • SYN flood an incomplete three-way handshake saturates the server
  • System performance excessive CPU and memory usage indicates an attack
Topic D9 · Incoming attacks

Signature vs statistical detection

System How it works Limitations
StatisticalDetects abnormal behaviourRequires extensive configuration; false positives easy; malicious traffic may go unnoticed
SignatureDetects known malicious activity from a signature databaseMust be constantly updated; only as good as its database
IDS / IPSCombine statistical and signature approachesNetwork-based (NIDS) or host-based (HIDS); e.g. Snort
Topic D9 · Incoming attacks

Email attacks

  • Problematic for both individuals and organisations
  • Range malicious attachments, mail bombing, phishing emails
  • Detect attachments with email malware scanners
  • Detect mail bombing the usual signs of DoS plus an increase in inbox storage
  • Manual phishing detection scrutinise the email for tell-tale signs

Topic D10 · Reconnaissance

Reconnaissance in the kill chain

  • The first kill-chain phase research, identify and select targets
  • External recon WHOIS, DNS, OSINT — everything from Unit U5
  • Internal recon after compromise, the attacker maps the environment
  • Purpose learn the network, find targets, plan the next move
  • Detect the pattern scans, probes, unusual lookups, enumeration traffic
Topic D10 · Reconnaissance

Indicators of reconnaissance

  • Scanning and probing many connections, rising ports, SYN patterns
  • Enumeration banner grabbing, service identification
  • DNS and WHOIS queries bulk lookups before an attack
  • Credential probing repeated login attempts
  • Correlate with logs firewall, IDS and web logs reveal the pattern
Topic D11 · Spread & escalation

Privilege escalation: vertical and horizontal

Type Meaning Example
VerticalGaining higher privileges than intendedA standard user escalating to administrator or root
HorizontalGaining the privileges of another user at the same levelUser A accessing User B's bank account
Permission creepAccumulated privileges beyond those requiredUsers keep old rights when roles change
Topic D11 · Spread & escalation

How privileges are escalated

  • Vertical methods user impersonation, Linux kernel manipulation, cross-zone scripting, shell injection, jailbreaking and rooting
  • Exploit common weaknesses theft or hijacking of unit cookies, predictable unit IDs, unit fixation, cross-site scripting
  • Weak credentials easily guessable passwords
  • Keystroke logging capturing credentials as they are typed
  • The result an attacker with more privilege than they should hold
Topic D11 · Spread & escalation

Testing for privilege escalation

  • Vertical testing try to reach a higher privilege level than intended
  • Horizontal testing attempt to access another user's account or data
  • unit weaknesses predictable unit IDs, unit fixation, cookie theft
  • Web application flaws cross-site scripting and access-control failures
  • Weak credentials guessable passwords and keystroke logging
Topic D11 · Spread & escalation

The compromise: from initial access to sensitive data

  1. Initial compromise
    the attacker gains a foothold
  2. Internal reconnaissance
    obtain and learn about the environment
  3. Seek additional targets
    find other systems to move to
  4. Escalate and move
    raise privileges and move around the network
  5. Gain access to sensitive resources
    the attacker reaches their objective
Topic D11 · Spread & escalation

Investigating escalation: audit logs

  • Audit logs Windows security logs, auth log, secure log
  • What to look for valid and invalid log-on attempts, newly created or modified user accounts
  • Command execution history ipconfig, ifconfig, tasklist, ps, traceroute, netstat
  • Task scheduler and registry scheduled tasks and registry entries
  • Network traffic review recent and active connections

Topic D11 · Spread & escalation

Scheduled tasks and registry

  • Scheduled tasks the use of 'at' or 'schtasks' to run code
  • Gain SYSTEM privileges tasks can run at high privilege
  • Run code under a compromised account persistence and execution
  • Registry keys can be modified easily — poor configuration leaves a system vulnerable
  • Detect via event IDs 106 registered, 140 updated, 141 removed
Topic D11 · Spread & escalation

Detecting malware spread within the network

  • Review recent and active connections current state of the network
  • Manual review of traffic and logs identify what is abnormal
  • Review abnormal connections unexpected destinations and protocols
  • Correlate across hosts the same infection on many systems indicates spread
Topic D13 · False positives

False positive acknowledgement

  • The risk automated tools flag many benign items as malicious
  • False dependence over-reliance on a single commercial tool
  • Acknowledge honestly state clearly what is a true positive and what is not
  • Corroborate use multiple vendors' data and analyse the results yourself
  • The professional standard conclusions must be defensible and reproducible
Topic D13 · False positives

Turning an alert into a finding

  1. Receive an alert
    from IDS, antivirus, or a manual review
  2. Validate the indicator
    is the signature or anomaly genuine?
  3. Corroborate across sources
    traffic, logs, multiple vendors, manual analysis
  4. Acknowledge the outcome
    true positive or false positive, stated clearly
  5. Document and report
    a defensible, evidence-backed conclusion
