Topic E10 · Infection vectors

Infected executables, DLLs and documents

  • Infected executables a payload injected into an expected friendly program
  • Masquerading malware disguised as a trusted application
  • Infected DLLs a small infection gives multiple executions
  • DLL hijacking and side-loading malicious DLL loaded in place of a legitimate one
  • Documents and macros macros directly malicious or unpacking payloads
  • File names .docx versus .docm reveal macro capability
Topic E10 · Infection vectors

JavaScript, drive-by downloads and passive exploitation

  • JavaScript notoriously insecure; allows code to run in the browser
  • Drive-by downloads install software without the user's knowledge
  • Also called drive-by installation used by rogue-antivirus software
  • Reliant on compromised websites e.g. the Mac Flashback exploit
  • Passive exploitation waits for a target; hunter versus snare
  • Malicious file-sharing sites a snare countered by search engines and browsers
Topic E10 · Infection vectors

USB, shared drives and email attacks

  • USB and external media shared between users; found drives; BadUSB; AutoRun
  • CDs and DVDs another removable-media infection path
  • Shared drives multiple access from trusted sources; potentially internet-facing
  • Email-based attacks social engineering manipulates users through psychology
  • File-name tricks e.g. Not_a_virus.jpg.exe hides the real extension
  • Defence mechanisms spam filters and user training

Topic E11 · Malware behaviour

Malware behaviours to look for

  • Persistence registry Run keys, services and scheduled tasks
  • Command and control C2 channels outbound to attacker infrastructure
  • Propagation spread across the network via shares and credentials
  • Data exfiltration staging and transmitting stolen data
  • Privilege escalation gaining higher rights on the host
  • Defence evasion disabling AV, hiding processes and files
Topic E11 · Anti-forensics

Anti-forensic techniques

  • Timestomping altering file timestamps to break the timeline
  • Log deletion clearing event logs and audit trails
  • Data hiding Alternate Data Streams and hidden files
  • Obfuscation packing and encrypting the payload
  • Artifact wiping clearing Prefetch, shadow copies and browser history
  • Detection avoidance shunning analysis environments and sandboxes
Topic E12 · Rootkits

What is a rootkit?

  • Rootkit malware that hides its presence from the operating system
  • Trojan horse components exploit, rootkit, downloader, dropper and binder
  • Symptoms system lockups, unauthorized changes, network glitches
  • Polymorphism changes appearance while keeping core functionality
  • Makes detection harder polymorphism is not specific to rootkits but complicates finding them
Topic E12 · Rootkits

Types of rootkit

Type Description
User-modeRuns at the application layer, intercepting API calls
Kernel-modeRuns at ring 0, intercepting system calls and drivers
User/kernel hybridCombines both to maximise control
Firmware rootkitHides within device firmware such as the BIOS
Virtual rootkitRuns as a hypervisor beneath the operating system
Topic E12 · Hooking

Hooking techniques: IAT and EAT

  • Two types of Windows hooks local and remote
  • IAT Import Address Table — the functions a program imports
  • IAT hooking redirecting an imported function to malicious code
  • EAT Export Address Table — the functions a DLL exports
  • EAT hooking redirecting exported functions to intercept calls
  • Inline API hooks patching the start of a function to jump elsewhere
Topic E12 · Hooking

Detecting IAT hooks

  1. Enumerate active processes
    walk the list of EPROCESS structures
  2. Enumerate loaded DLLs
    examine the PEB or VAD; record names, base addresses and sizes
  3. Dump and rebuild
    dump the process and loaded DLLs to parse the PE header and locate the IAT
  4. Verify function addresses
    check each imported function address falls within the owning DLL
Topic E12 · Hooking

SSDT hooking

  • SSDT System Service Descriptor Table (or Dispatch Table)
  • Kernel hooking rootkits patch SSDT entries to hide files, processes and connections
  • Detecting SSDT hooks compare table entries against the original kernel addresses
  • Kernel-mode rootkits operate at ring 0 where they have the most control
  • Impact can hide malicious processes and intercept network activity
Topic E12 · Keyloggers

User-space keyloggers

  • Typically use the Windows API calling SetWindowsHookEx to install a hook
  • SetWindowsHookEx parameters idHook, lpfn, hMod and dwThreadId
  • WH_KEYBOARD and WH_KEYBOARD_LL low-level keyboard hooks
  • Hook injection the hook function receives each keystroke
  • Other hook types inline API hooks and driver IRP hooks
Topic E13 · Live analysis

Live malware analysis in the sandbox

  • Controlled environment an isolated VM or sandbox, snapshot before execution
  • Process monitoring observe process creation and parent/child relationships
  • File and registry monitoring see what the sample creates and modifies
  • Network monitoring capture C2 connections and DNS lookups
  • Do not remediate identify behaviour, do not clean during analysis
  • Multiple tools cross-check results across several monitors
Topic E13 · Live analysis

The live analysis workflow

  1. Prepare the environment
    a clean, snapshot-able sandbox that mirrors the target
  2. Execute the sample
    run it and observe its immediate actions
  3. Monitor behaviour
    processes, files, registry, network and services
  4. Collect artefacts
    capture logs, dumps and network traffic
  5. Analyse and report
    document the behaviour and its indicators of compromise
