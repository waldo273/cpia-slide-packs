## 4. Drill-D2 - Correlate four log sources

**35 minutes. Runs on kali. Data: authored proxy, firewall, DHCP and DNS logs.**

**Objective.** Correlate proxy, firewall, DHCP and DNS logs into one host story.

**Run this.**

```bash
grep -c ping3.dyngate.com /labs/work/logs/dns.log
grep '45.125.66.32' /labs/work/logs/proxy.log
head -2 /labs/work/logs/dhcp.log
grep ALLOW /labs/work/logs/firewall.log | head -4
```

**What good looks like.**

```text
686 DNS queries to ping3.dyngate.com, one proxy CONNECT to 45.125.66.32:2917,
a DHCP lease naming 10.1.17.215 as WIN-FIN-0427, and firewall ALLOW lines for the same two
destinations. One joined row: 09:02:11, WIN-FIN-0427 at 10.1.17.215, to 45.125.66.32:2917, lease
from 08:41:12, DNS polling every 5 seconds.
```

**Save this evidence:** `correlation table` in `/labs/reports/`.

**Pass criterion.** One row joins at least three log sources by time and host.

**Common mistake.** Reading each log in isolation and missing the lease that names the host.

## 5. Drill-D3 - Spot misconfigured firewall rules

**30 minutes. Runs in the container. Data: firewall and DNS configuration.**

**Objective.** Find network configuration faults that an attacker can use.

**Run this.**

```bash
grep -E '2917|:53' /labs/work/logs/firewall.log
head -4 /labs/work/logs/firewall.log
grep -c ping3.dyngate.com /labs/work/logs/dns.log
```

**What good looks like.**

```text
Two faults in the fixture: outbound TCP 2917 is allowed to a single external host,
which no business rule explains, and DNS is allowed to any on port 53, which permits tunnelling
and external resolvers. The third finding is the volume: 686 queries to one name in under an hour
would have shown in the log the rule base never inspects.
```

**Save this evidence:** `findings table` in `/labs/reports/`.

**Pass criterion.** Each fault quotes the configuration line that causes it.

**Common mistake.** Listing best practice advice instead of faults present in the evidence.

## 6. Drill-D4 - Verify a protocol on a non-standard port

**30 minutes. Runs in the container. Data: authored non standard port capture.**

**Objective.** Prove what protocol is running on a non standard port.

**Run this.**

```bash
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tcp.port==2917' -c 5
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tcp.port==2917' -T fields -e frame.time_relative -e ip.src -e tcp.len | head -8
```

**What good looks like.**

```text
889.6  10.1.17.215  0
889.8  45.125.66.32  0
889.8  10.1.17.215  119
889.9  45.125.66.32  1038

Port 2917 on 45.125.66.32 carries a short request and a long reply, with no HTTP or TLS preamble,
so the protocol is unidentified and must be reported as such.
```

**Save this evidence:** `protocol proof` in `/labs/reports/`.

**Pass criterion.** The learner says unidentified rather than guessing, and lists the fields checked.

**Common mistake.** Naming a protocol because the port number looks familiar.

## 7. Drill-D5 - Measure beacon interval and jitter

**35 minutes. Runs in the container. Data: 2025 traffic pcap.**

**Objective.** Measure periodicity and decide whether it proves beaconing.

**Run this.**

```bash
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tcp.flags.syn==1 && tcp.flags.ack==0 && ip.dst==45.125.66.32' -T fields -e frame.time_relative
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'dns' -T fields -e dns.qry.name | sort | uniq -c | sort -rn | head -5
```

**What good looks like.**

```text
9 TCP connection attempts, intervals 13.7, 8.8, 1508.3, 12.5, 8.8, 143.1, 12.3, 8.8 seconds:
paired bursts, not a fixed interval.

DNS shows 686 queries to ping3.dyngate.com (confirmed again from the log fixture with grep -c),
64 to wpad.bluemoontuesday.com, 43 to www.bing.com.

Conclusion: the DNS name polling is the periodic signal, the TCP pattern is not.

Ignore the tshark line "Running as user root and group root. This could be dangerous.", it is a
warning about capture privileges, not about the output.

Measured on the range: 0.49 s for the SYN query, 0.38 s for the DNS query.
```

**Save this evidence:** `interval histogram, jitter value` in `/labs/reports/`.

**Pass criterion.** Intervals are computed, not eyeballed, and the weaker signal is named as weaker.

**Common mistake.** Calling any repeated connection a beacon without measuring the interval.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.
