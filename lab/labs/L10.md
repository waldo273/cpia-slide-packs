  what looks like real personal data in a public corpus, stop, do not copy it, and tell the

## 4. Drill-E4 - Prefetch, shimcache and event logs

**35 minutes. Runs in the container. Data: evtx corpus and disk image.**

**Objective.** Build a timeline of process execution from Windows event logs.

**Run this.**

```bash
ls '/labs/artifacts/evtx-attack-samples/Execution' | head -4
plaso-log2timeline --status_view none -z UTC --storage_file /labs/work/U09-E4.plaso '/labs/artifacts/evtx-attack-samples/Execution'
plaso-psort -q -o l2tcsv -w /labs/reports/U09-E4.csv /labs/work/U09-E4.plaso
grep -E ',EVT,' /labs/reports/U09-E4.csv | grep -oE '\[4[0-9]{3} ' | sort | uniq -c | head
```

**What good looks like.**

```text
Exec_sysmon_meterpreter_reversetcp_msipackage.evtx
Sysmon_Exec_CompiledHTML.evtx
Sysmon_meterpreter_ReflectivePEInjection_to_notepad_.evtx

1,063 rows written to /labs/reports/U09-E4.csv

      4 [4698
      4 [4699

Four task creations and four deletions, alongside the Sysmon execution records. The timeline is the
artefact: it puts the script host, the injected process and the scheduled task into one ordered file,
which is what makes the sequence arguable.
```

**Save this evidence:** `artefact table` in `/labs/reports/`.

**Pass criterion.** Timeline produced and at least two event ids identified.

**Common mistake.** Trying to read EVTX as text instead of parsing it.

## 6. Drill-E6 - USB history and autorun from the registry

**35 minutes. Runs on kali. Data: ntfs1.raw, converted from the E01.**

**Objective.** Recover registry evidence from a memory image when the disk image has no hives.

**Run this.**

```bash
vol -q -f /labs/work/jo-2009.mem windows.registry.hivelist
vol -q -f /labs/work/jo-2009.mem windows.registry.printkey --key 'ControlSet001\Enum\USBSTOR' | head -8
```

**What good looks like.**

```text
0xe1388b60  \Device\HarddiskVolume1\WINDOWS\system32\config\software   Disabled
0xe13886b8  \Device\HarddiskVolume1\WINDOWS\system32\config\default    Disabled
0xe149db60  \Device\HarddiskVolume1\WINDOWS\system32\config\SECURITY   Disabled

Key  ...\ControlSet001\Enum\USBSTOR   (keys listed, no values)

The NTFS image in this lab carries no registry hives, so memory is the source of truth. The USBSTOR
keys exist but hold no device values, which is a finding in its own right: there is no USB history to
report, and the drill is not to invent one from a key name alone.
```

**Save this evidence:** `USB timeline` in `/labs/reports/`.

**Pass criterion.** Hives listed from memory, with the empty USBSTOR result reported as absence.

**Common mistake.** Reporting USB devices that the hive does not contain.

## 7. Drill-E7 - Hash sets, strings and fuzzy hashing

**30 minutes. Runs in the container. Data: malware sample set.**

**Objective.** Classify suspect files with hashes, strings and a YARA rule.

**Run this.**

```bash
sha256sum /labs/artifacts/malware/samples/*
yara -r /labs/artifacts/malware/yara_rules.yar /labs/artifacts/malware/samples
strings -n 8 /labs/artifacts/malware/samples/cobalt_like.dll | head
```

**What good looks like.**

```text
Simulated_Dropper_Stage      wsrdropper_2025.bin
Simulated_Ransomware_Decryptor_Note  ransom_note.txt.sample
Simulated_Emotet_Downloader  emotet_like.elf
Simulated_CobaltStrike_Beacon  cobalt_like.dll
Simulated_Benign_PE_Baseline  cobalt_like.dll

Note the last line: the benign baseline rule also fires, which is the false positive to explain.
```

**Save this evidence:** `hash set, similarity note` in `/labs/reports/`.

**Pass criterion.** Hash set built, rule hits listed, and the double hit explained.

**Common mistake.** Reporting a YARA match as proof of malware.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.

## If you are ahead, or behind

- Ahead: take the last drill and redo it with the tool's limitation tested, for example run the same query a second way and reconcile the answers.
- Behind: drop the last drill and keep the evidence review. Never drop the handover brief, it is where the learning lands.
