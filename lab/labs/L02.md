## 4. Drill-B1 - Verify the protocol, do not trust the port

**30 minutes. Runs in the container. Data: 2025 traffic pcap.**

**Objective.** Verify a protocol from its bytes rather than from the port number.

**Run this.**

```bash
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -q -z io,phs | head -20
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tcp.port==2917' -c 5
```

**What good looks like.**

```text
A table of protocol, port seen, protocol proven from the payload, and the field used.
Port 2917 carries traffic that is not identified by the port, so the row must say how it was
identified instead of guessing.
```

**Save this evidence:** `protocol table with packet evidence` in `/labs/reports/`.

**Pass criterion.** Every row names the field that proves the protocol, not the port number.

**Common mistake.** Assuming port 80 means HTTP, then missing a tunnel that also uses port 80.

## 5. Drill-B2 - Draw the range topology from evidence

**30 minutes. Runs in the container. Data: ip addr, routes, listening sockets.**

**Objective.** Map the network this lab runs on, and say which interface owns which route and which
port is served by which process.

**Run this.**

```bash
ip -br addr
ip route
ss -ltnp | head -8
```

**What good looks like.**

```text
lo               UNKNOWN        127.0.0.1/8 ::1/128
eth0             UP             172.17.0.2/16

default via 172.17.0.1 dev eth0
172.17.0.0/16 dev eth0 proto kernel scope link src 172.17.0.2

LISTEN 0 128 0.0.0.0:2222  0.0.0.0:*  users:(("sshd",pid=...,fd=3))
LISTEN 0 128 0.0.0.0:8010  0.0.0.0:*  users:(("python3",pid=...,fd=3))
LISTEN 0 128 0.0.0.0:8080  0.0.0.0:*  users:(("python3",pid=...,fd=3))
```

Every service this lab uses answers inside this one container: the victim web service on 8080, the
victim shell on 2222, the evidence server on 8010. There is no second host to reach and no range to
start, which is why the whole lab fits in a single Kali container.

**Save this evidence:** `topology diagram, socket table` in `/labs/reports/`.

**Pass criterion.** Each interface named with the network it carries, and each listening port paired
with the process that owns it.

**Common mistake.** Reading the port number and assuming the service, instead of checking the process.

## 6. Drill-B4 - Passive and active OS fingerprinting

**30 minutes. Runs in the container. Data: the victim service on 127.0.0.1.**

**Objective.** Fingerprint an operating system passively and actively, and say which is safer.

**Run this.**

```bash
nmap -Pn -n -O --osscan-guess 127.0.0.1
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'ip.ttl' -T fields -e ip.ttl | sort | uniq -c | head
```

**What good looks like.**

```text
22/tcp   open  ssh
8080/tcp open  http-proxy
Aggressive OS guesses: Linux 4.15 - 5.19 (97%), Android 11 (Linux 4.9) (93%),
Android 12 (Linux 5.4) (93%), Linux 3.8 (93%), OpenWrt 21.02 (Linux 5.4) (93%),
MikroTik RouterOS 7.2 - 7.5 (Linux 5.6.3) (93%)
Nmap done: 1 IP address (1 host up) scanned in 11.32 seconds

Ten guesses within four points of each other. The learner must say that this narrows the kernel
family and nothing else, and that the active scan itself is now in the target's logs.

Measured on the range: 11.3 s for the OS scan.
```

**Save this evidence:** `TTL and window table, nmap -O` in `/labs/reports/`.

**Pass criterion.** Both methods present, and the evidence cost of the active scan stated.

**Common mistake.** Quoting the 97 percent as a version, when the range spans four major kernels.

## 7. Drill-B5 - Banners, user agents and application versions

**30 minutes. Runs in the container. Data: victim web server and its logs.**

**Objective.** Identify server and client software versions from banners, headers and metadata.

**Run this.**

```bash
curl -sI http://127.0.0.1:8080 | head -8
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'http.user_agent' -T fields -e http.user_agent | sort -u | head
```

**What good looks like.**

```text
A version table: component, version, source of the evidence, confidence. At least one
row must come from metadata rather than a banner.
```

**Save this evidence:** `version table` in `/labs/reports/`.

**Pass criterion.** Each version is tied to the exact field it came from.

**Common mistake.** Trusting a spoofed user agent as proof of the client version.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.

- Behind: drop the last drill and keep the evidence review. Never drop the handover brief, it is where the learning lands.
