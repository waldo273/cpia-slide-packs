  this course is static analysis only.

## 4. Drill-C1 - WHOIS and IP registry for a domain

**25 minutes. Runs on kali + internet. Data: training domain.**

**Objective.** Read the registration records of a domain and of a command address.

**Run this.**

```bash
whois crest-approved.org | head -14
whois 5.252.153.241 | head -12
```

**What good looks like.**

```text
Domain Name: crest-approved.org
Registrar WHOIS Server: http://whois.cloudflare.com
Creation Date: 2006-10-17T10:02:18Z
Registry Expiry Date: 2027-10-17T10:02:18Z
Registrar: Cloudflare, Inc.
Name Server: rob.ns.cloudflare.com
Name Server: vera.ns.cloudflare.com

% Information related to '5.252.153.0 - 5.252.153.255'
% Abuse contact for '5.252.153.0 - 5.252.153.255' is 'a99423123@gmail.com'

Run these on 127.0.0.1: the host has no whois client. The domain is twenty years old and hidden
behind a privacy service, which tells you the registrar and nothing about intent. The address sits in
a /24 registered with a free mail abuse contact, and that mismatch between an established domain and
a cheaply held address block is the point to carry into the traffic analysis.
```

**Save this evidence:** `registry facts table` in `/labs/reports/`.

**Pass criterion.** Both records read, with the domain age weighed against the address block.

**Common mistake.** Judging intent from a domain name that is two decades old.

## 5. Drill-C2 - DNS records, zone transfer and fast flux

**30 minutes. Runs on kali + internet. Data: training domain.**

**Objective.** Pull DNS records and judge whether the domain looks fast flux.

**Run this.**

```bash
dig +short soa crest-approved.org
dig +short mx crest-approved.org
dig +short txt google.com | head -3
dig axfr crest-approved.org @rob.ns.cloudflare.com
```

**What good looks like.**

```text
rob.ns.cloudflare.com. dns.cloudflare.com. 2417901415 10000 2400 604800 1800
0 crestapproved-org01c.mail.protection.outlook.com.

; Transfer failed.

TXT is a long list on a real domain: SPF, several site verification tokens, a docusign token and
one bare base64 string, Z29vZ2xl, which decodes to google. The values change, so the card is about
the pattern, not the strings. A failed transfer is a result, not a tool error.

Measured on the range: 19 ms, 16 ms, 40 ms and 57 ms per dig call.
```

**Save this evidence:** `record table, flux reasoning` in `/labs/reports/`.

**Pass criterion.** SOA, MX and TXT each present, the transfer result recorded, and one TXT string decoded.

**Common mistake.** Reporting a failed transfer as a broken tool.

## 6. Drill-C3 - Enumerate a public footprint

**35 minutes. Runs on kali + internet. Data: training domain.**

**Objective.** Enumerate a domain from public records without touching the target.

**Run this.**

```bash
dig +short a crest-approved.org
dig +short ns crest-approved.org
dig +short txt crest-approved.org | head -3
curl -sI https://crest-approved.org | head -6
```

**What good looks like.**

```text
141.193.213.21
141.193.213.20

rob.ns.cloudflare.com.
vera.ns.cloudflare.com.

"MS=ms83455807"
"anthropic-domain-verification-65g332=SuEIrQoWBwTMrZA20n1pJhm5T"
"apple-domain-verification=00AZyZ3SLUpipkjz"

HTTP/2 301
content-type: text/html; charset=UTF-8
location: https://www.crest-approved.org/
server: cloudflare

Two addresses behind Cloudflare, the authoritative name servers, and a 301 to www. The TXT records
leak the vendors the owner has verified with, because domain verification strings are public by
design. All of this comes from third parties, so the target sees nothing.
```

**Save this evidence:** `footprint page` in `/labs/reports/`.

**Pass criterion.** Addresses, name servers and at least one non-address record explained.

**Common mistake.** Port scanning the target when public records already answer the question.

## 7. Drill-C4 - Document metadata across formats

**25 minutes. Runs on kali. Data: authored PDF and DOCX.**

**Objective.** Extract document metadata and say which field is evidentially useful.

**Run this.**

```bash
exiftool /labs/work/samples/report.pdf
exiftool /labs/work/samples/report.docx
pdfid /labs/work/samples/report.pdf
```

**What good looks like.**

```text
ExifTool Version Number         : 13.55
File Name                       : sample.pdf
File Size                       : 69 bytes
File Modification Date/Time     : 2026:10:20 18:46:15+00:00

plus the author and producer fields where present. One line on which field links the document to
an author or a machine.
```

**Save this evidence:** `metadata table` in `/labs/reports/`.

**Pass criterion.** Author, producer and the created date are read, and one is named as the useful link.

**Common mistake.** Trusting a metadata date that the author can edit.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.

- Ahead: take the last drill and redo it with the tool's limitation tested, for example run the same query a second way and reconcile the answers.
- Behind: drop the last drill and keep the evidence review. Never drop the handover brief, it is where the learning lands.
