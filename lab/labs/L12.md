## 4. Drill-F2 - Find send and receive loops in a binary

**35 minutes. Runs on kali. Data: cobalt_like.dll.**

**Objective.** Identify send and receive loops and persistence in a binary without running it.

**Run this.**

```bash
strings -n 8 /labs/artifacts/malware/samples/cobalt_like.dll | head -12
strings -n 8 /labs/artifacts/malware/samples/cobalt_like.dll | grep -iE 'http|pipe|jitter|agent'
```

**What good looks like.**

```text
https://cdn.static-resources.test/microsoft-ph-update
\.\pipe\MSSE-2679-server
jitter 25%
Mozilla/5.0 (Windows NT 10.0; Win64; x64)

Four strings that together describe a beacon: a URL, a local pipe, a jitter setting and a user
agent. The learner must map each to a function.
```

**Save this evidence:** `annotated disassembly` in `/labs/reports/`.

**Pass criterion.** Each string is mapped to a capability, and the mapping is justified.

**Common mistake.** Listing strings and calling the file malicious without mapping any to behaviour.

## 5. Drill-F6 - Crypto constants and key handling

**35 minutes. Runs on kali. Data: emotet_like.elf.**

**Objective.** Find cryptographic constants and key handling in a sample.

**Run this.**

```bash
strings -n 8 /labs/artifacts/malware/samples/emotet_like.elf | head -12
strings -n 8 /labs/artifacts/malware/samples/emotet_like.elf | grep -E '^[A-Za-z0-9+/=]{16,}$' | head -3
echo ZXZhc2lvbl9qdW5rX2My | base64 -d
```

**What good looks like.**

```text
hxxp://update.cdn-sync.test/files/setup.exe
Global\MSUpdate_8f3a91
HKCU\Software\Microsoft\Windows\CurrentVersion\Run

The only base64 shaped string is ZXZhc2lvbl9qdW5rX2My, which decodes to:

evasion_junk_c2

So it is encoding, not encryption, and the label names the technique. The learner must say which
of the three strings is crypto, which is a path and which is a label.
```

**Save this evidence:** `constants table, key note` in `/labs/reports/`.

**Pass criterion.** A constant or blob is identified, and the claim is labelled encryption or encoding.

**Common mistake.** Calling a base64 blob encrypted.

## 6. Drill-F8 - PE headers, sections and the import table

**35 minutes. Runs on kali. Data: wsrdropper_2025.bin and cobalt_like.dll.**

**Objective.** Read a PE header and say what the structure reveals.

**Run this.**

```bash
python3 - <<'EOF'
import struct
d=open('/labs/artifacts/malware/samples/cobalt_like.dll','rb').read()
off=struct.unpack('<I', d[0x3c:0x40])[0]
print('MZ', d[:2], 'e_lfanew', hex(off), 'sig', d[off:off+4])
print('machine', hex(struct.unpack('<H', d[off+4:off+6])[0]), 'sections', struct.unpack('<H', d[off+6:off+8])[0])
EOF
```

**What good looks like.**

```text
MZ b'MZ' e_lfanew 0x40 sig b'PE\x00\x00'
machine 0x8664 sections 2

x86-64, two sections, and a very small file. The learner must say which of those facts is
suspicious and which is merely small.

Measured on the range: 17 ms for the header read.
```

**Save this evidence:** `header table` in `/labs/reports/`.

**Pass criterion.** Machine type and section count are read from the header, not guessed.

**Common mistake.** Reporting a packer because the file is small.

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.
