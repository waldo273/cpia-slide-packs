## 4. Drill-B6 - Read and test a firewall rule base

**25 minutes. Runs in the container. Data: host ufw ruleset.**

**Objective.** Prove which ports a host actually exposes, and explain a firewall that disagrees.

**Run this.**

```bash
sudo ufw status numbered | head -8
nmap -Pn -p 8010,8040,8080,9177 127.0.0.1
```

**What good looks like.**

```text
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] 22/tcp                     ALLOW IN    172.16.0.0/16
[ 2] 3389/tcp                   ALLOW IN    172.16.0.0/16

PORT     STATE  SERVICE
8010/tcp open   xmpp
8040/tcp open   ampify
8080/tcp closed http-proxy
9177/tcp open   unknown

ufw allows 22 and 3389 only, yet three other ports answer. They are published container ports, and
Docker writes its own iptables rules ahead of the ufw chain, so a container port is reachable even
though no ufw rule mentions it. Port exposure has two control planes and ufw is only one of them.
```

**Save this evidence:** `rule audit, test results` in `/labs/reports/`.

**Pass criterion.** Names the Docker iptables bypass instead of calling the firewall faulty.

**Common mistake.** Reading ufw alone and concluding the host exposes only two ports.

## 5. Drill-B7 - Hash, HMAC and symmetric encryption

**30 minutes. Runs on kali. Data: supplied sample files.**

**Objective.** Produce a hash, an HMAC and a symmetric decryption, and explain the difference.

**Run this.**

```bash
sha256sum /labs/artifacts/malware/samples/wsrdropper_2025.bin
openssl dgst -sha256 -hmac 'course-key' /labs/artifacts/malware/samples/wsrdropper_2025.bin
openssl enc -aes-256-cbc -d -pbkdf2 -in /labs/work/samples/payload.enc -pass pass:course
```

**What good looks like.**

```text
cb898f47fa1a0e5332b4b7968807144d86ca6bc8528f95b1814e0336acc3bc63  wsrdropper_2025.bin

plus an HMAC line and a decrypted payload. Three lines of explanation: hash is one way, HMAC
proves integrity and origin, symmetric decryption needs the key.
```

**Save this evidence:** `hash sheet, openssl transcript` in `/labs/reports/`.

**Pass criterion.** The sha256 matches the recorded value, and the three definitions are correct.

**Common mistake.** Calling base64 encoding encryption.

## 6. Drill-B8 - Find cryptography in use in a capture

**30 minutes. Runs in the container. Data: 2025 traffic pcap.**

**Objective.** Read the cryptography in a capture without decrypting anything.

**Run this.**

```bash
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tls.handshake.type==1' -T fields -e ip.dst -e tls.handshake.extensions_server_name | head -6
tshark -r /labs/artifacts/2025-01-22-traffic-analysis-exercise.pcap -Y 'tls.handshake.type==2' -T fields -e tls.handshake.ciphersuite | head -3
```

**What good looks like.**

```text
23.40.146.4      kv801.prod.do.dsp.mp.microsoft.com
52.156.123.84    geo.prod.do.dsp.mp.microsoft.com
20.10.31.115     client.wns.windows.com
52.178.17.235    v10.events.data.microsoft.com
204.79.197.203   windows.msn.com

0xc030
0xc02c
0xc030

0xc030 is ECDHE with RSA and AES-256-GCM under SHA-384; 0xc02c is its ECDSA equivalent. The server
names show a Windows host reporting to Microsoft telemetry. Neither field reveals content: the server
name is sent in clear by design, and the cipher suite is negotiated metadata, so this is the ceiling
of what a capture gives without keys.
```

**Save this evidence:** `handshake table, cipher note` in `/labs/reports/`.

**Pass criterion.** Names both cipher suites and states what stays unreadable.

**Common mistake.** Claiming the traffic cannot be analysed because it is encrypted.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.
