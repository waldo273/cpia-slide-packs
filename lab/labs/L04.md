## 4. Drill-B9 - Windows and registry permissions

**30 minutes. Runs in the container. Data: ntfs1-gen2.E01 image.**

**Objective.** Read permissions and ACLs from a Windows image and from a registry hive.

**Run this.**

```bash
fls -r /labs/work/disk/ntfs1.raw | head -20
icat /labs/work/disk/ntfs1.raw 6-128-1 > /labs/reports/U02-B9-bitmap.bin
```

**What good looks like.**

```text
r/r 6-128-1:   $Bitmap
r/r 4-128-4:   $AttrDef
d/d 11-144-4:  $Extend

plus the extracted bitmap, 6-128-1, which is the allocation map for the volume.

A table of object, owner, and the permission that matters for the case. One row must explain why an
ACL on a registry key is a persistence control, not just a file permission.
```

**Save this evidence:** `ACL table, SID note` in `/labs/reports/`.

**Pass criterion.** The table names the owner and one inherited versus explicit permission.

**Common mistake.** Reading Linux style mode bits on an NTFS image.

## 5. Drill-B10 - Processes, sockets and patch level

**25 minutes. Runs in the container. Data: the victim service on 127.0.0.1.**

**Objective.** Profile a live host you did not build, using only the tools it carries.

**Run this.**

```bash
ssh -i /root/.ssh/id_lab -p 2222 analyst@127.0.0.1 'ps -o pid,ppid,vsz,args'
ssh -i /root/.ssh/id_lab -p 2222 analyst@127.0.0.1 'lsof -nP -i 2>/dev/null | head -6'
ssh -i /root/.ssh/id_lab -p 2222 analyst@127.0.0.1 'cat /etc/os-release | head -3; ls /bin | wc -l'
```

**What good looks like.**

```text
1     0 1636 sh /script.sh
 19     1 6640 sshd: /usr/sbin/sshd -E /var/log/auth.log [listener]
 22     1 9.8m tcpdump -i eth0 -U -w /var/log/network.pcap
 23     1  20m python3 /webapp.py

321  /bin/busybox  0  pipe:[59487052]

NAME="Alpine Linux"
ID=alpine
VERSION_ID=3.20.10
82

The victim is Alpine with 82 binaries, so ss and dpkg are absent and lsof is what works. The host is
already collecting its own traffic to /var/log/network.pcap while python3 serves the web app, so the
analyst reads the running collection before choosing tools. Adapting to the host beats pasting
commands from a distribution it is not.
```

**Save this evidence:** `ps and ss output, patch list` in `/labs/reports/`.

**Pass criterion.** Identifies the running collection and adapts to the toolset present.

**Common mistake.** Running ss and dpkg on a BusyBox host that has neither.

## 6. Drill-B11 - Email headers, certificates and encoding

**30 minutes. Runs on kali. Data: authored .eml and certificate.**

**Objective.** Read an email header, a certificate and an encoded payload correctly.

**Run this.**

```bash
cat /labs/work/samples/phish.eml | head -40
openssl x509 -in /labs/work/samples/cert.pem -noout -subject -issuer -dates
echo 'SGVsbG8gYW5hbHlzdA==' | base64 -d
```

**What good looks like.**

```text
Three verdicts: the true sender domain from the header chain, the certificate validity
window and issuer, and the decoded payload. One sentence on which header field is easiest to forge.
```

**Save this evidence:** `header verdict, decoded payload` in `/labs/reports/`.

**Pass criterion.** The sender verdict cites the field it came from, and the base64 decode is correct.

**Common mistake.** Reading From instead of Return-Path and Received.

## Handover brief

Two minutes at the end. Each learner answers three questions out loud, in 90 seconds:

1. **Finding.** One sentence a client would understand. No tool names.
2. **Limitation.** What this evidence cannot tell you, and why.
3. **Next step.** The single next action you would take, and who authorises it.

Record the three answers in `/labs/reports/` as the lab's closing note. This is group A4, record keeping, in practice.
